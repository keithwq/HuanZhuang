# ADR-003 · 纹理加载与内存策略（含 DPR=3 设备策略，CAL-04 工程定稿）

> 状态：**已定稿** · 2026-11-21 · 程基岩（engineering-lead）
> 决策依据：decisions.md D2-01（全量双视图 + 懒加载）、D1-11（动效白名单）；美术圣经 §5.5（CAL-04 升级项：稳态 ≤45MB / 峰值 ≤75MB / 房间 ≤60MB / DPR=3 策略）；GDD：paperdoll-render §2.2/§4、wardrobe-tryon §4、room-decoration §4
> 数值核算：见 `docs/architecture/cal-04-review.md`（CAL-04 核对单，本 ADR 引其结论）

## 上下文

三条内存预算线（美术圣经 §5.5）+ 一条待定策略（DPR=3）是本项目最大工程风险面：

1. 稳态 ≤45MB：任意时刻常驻**当前视图**全 13 槽贴图 + BODY 背面基底 + UI 底图；
2. 峰值 ≤75MB：旋转 300ms 过渡窗口内正/背两套短时共存，完成后**立即卸载旧视图**；
3. 房间 ≤60MB：720×1280 单屏 + 21 点位家具 + 3 张预烘焙氛围光分层（room-decoration §4.3）；
4. DPR=3 设备（iPhone Pro 档）：若按 GDD §4 公式"逻辑尺寸 × DPR² × 4B"直译，13 槽稳态即 ≈52MB（未计 UI/背景），三档预算全线击穿——**必须定稿缩放链策略**。

## 备选方案（DPR=3 策略）

| 方案 | 描述 | 稳态估算（最坏 bbox 口径，见 cal-04-review §2） | 结论 |
|---|---|---|---|
| A. 纹理与渲染均按原生 DPR=3 | 部件贴图按 3× 导入，画布按 DPR=3 建 | ≈52MB 部件 + ≈33MB 帧缓冲 + UI ≈ **90MB+** | 三档预算全破，否决 |
| B. 纹理 1×（512×1024）+ 渲染上限 DPR=2 | 贴图按逻辑尺寸导入，GPU 上采样 | ≈6MB 部件（极省） | 内存极优，但线稿 2× 上采样发虚，与"手绘线条有呼吸"（美术支柱 3）冲突；作为**降级档保留** |
| C. 部件 @2× 导入 + 渲染上限 DPR=2 + 背景类 @1× | 分资产密度策略 | ≈23MB 部件 + 全项 ≈ **44MB** | **采纳** |

## 决定

### 1. DPR 缩放链定稿（方案 C）

```
源稿 2×（1024×2048，美术管线不变，美术圣经 §5.5）
  ├─ 角色/服装部件、UI 图集、图标、家具 → 按 @2× 导入（= 源稿尺寸直接发布）
  └─ 背景整图、氛围光分层、光效贴图 → 按 @1× 导出（512/720 逻辑尺寸）
渲染口径：canvas 后备存储 = CSS 尺寸 × min(deviceDPR, 2)   ← 渲染上限钉死 2×
游戏逻辑坐标：固定逻辑宽 720（hud-layout §4 换算规则），高度随屏比自适应
```

- **质量论证**：部件线稿在 2× 密度下于 DPR=3 设备表现为 1.5 设备像素/纹素，扁平手绘风（美术支柱 3：不追写实）视觉损失不可感知；背景是软渐变/暗纹内容，1× 上采样不可见（cal-04-review §4.1 实测口径）；
- **收益**：部件内存 = 逻辑 bbox × 4 × 4B（比方案 A 省 56%）；帧缓冲 720×~1600 ≈ 4.6MB（比 DPR=3 全尺寸省 ≈19MB）；DPR=3 高端机纹理总量回到三档预算内；
- **执行机制**：`BootScene` 读 `window.devicePixelRatio`，`renderScale = min(dpr, 2)` 写入引擎常量；资产 URL 由 `@2x/@1x` 目录约定 + 资产清单表驱动，**不依赖运行时嗅探降采样**。

### 2. 三档预算的执行机制：TexMemAccountant（纹理预算会计）

新增 `src/texmem/` 模块，全项目**唯一**的纹理进出登记处（包装 Phaser Loader/TextureManager）：

```
TexMemAccountant
├── register(key, w, h)      // 载入即登记：estBytes = w×h×4（GPU 未压缩口径）
├── release(key)             // 卸载即销记 + textures.remove(key)（GPU 释放）
├── assertBudget(tier)       // 三档阈值表：DRESS_STEADY 45 / FLIP_PEAK 75 / ROOM 60（MB）
│     超阈值 → 开发态硬断言（console.assert + 构建期可 fail）；生产态 console.warn
└── report()                // 供 Phase 5 性能验收导出（测试证据路径 tests/evidence/texmem-*.md）
```

- 估算口径与 cal-04-review 一致（w×h×4，RGBA 未压缩）——**保守口径**（真实 GL 内部格式/对齐略小），验收以实测为准、预算以估算设闸。

### 3. 懒加载触发定稿（paperdoll-render §2.2 工程化）

| 事件 | 动作 |
|---|---|
| 首启/读档 | 载入当前视图全 13 槽（默认套装或存档套装）+ BODY 正背两基底 + UI 底图 + 背景类 |
| 翻转触发（手势/按钮） | **立即启动 300ms 剪影过渡**（不等纹理）+ 并行预载目标视图贴图 |
| 过渡结束（t=T） | **立即卸载旧视图贴图**（release + textures.remove）——峰值窗口硬上限 ≈300ms |
| 纹理迟到 | 剪影照常走完 → 旧视图淡切到新视图补完（GDD §5.3：宁可晚 100~200ms 不出空槽） |
| 过渡进行中再翻转 | 忽略（无队列，GDD §5.3） |
| 试穿当前视图新部件 | 载入单件；**同视图旧件在"非当前穿着组合"中无引用时立即卸载**（每槽仅 1 件常驻，13 槽 × 当前视图 = 固定集合，试穿不产生累积） |

- **同视图缓存规则**：当前穿着的 13 件 = 常驻集合，唯一例外是试穿被打断链上的中间件（立即卸载，不保留）——杜绝"摆弄 10 分钟后内存爬升"。

### 4. 衣柜缩略图（wardrobe-tryon §3/§4 口径落地）

- 缩略图 @2×（208×208 导入），单页签常驻 ≤20 张 + 上下缓冲 1 行，滚动视口外**不挂载**（不加载）；
- 切页签时旧页签缩略图批量 release（40~50 件全量常驻无必要，页签级 LRU）；
- 估算 ≈3.5MB/页签（计入稳态预算的 UI 份额，见 cal-04-review §2）。

### 5. 房间场景（room-decoration §4 口径落地）

- 进入 room 模式：载入房间背景 + **已摆放家具**贴图（按 placement，非全 30 件目录）+ 当前档位氛围光分层；
- 家具抽屉缩略图同 §4 页签级 LRU；
- 氛围光分层按档位开关（棘轮只升不降）；**预载下一档分层**在 occupied 逼近阈值（差 1 点位）时执行，避免档位瞬间触发时才加载造成 >300ms 延迟；
- 退出 room 模式：全量 release 房间侧纹理，回到换装稳态——dress ⇄ room 切换内存互斥、不叠加。

### 6. 降级档（方案 B 保留为低端机路径）

- WebGL amount 充足时：方案 C 全量；
- Canvas2D 回退（WebGL 不可用）或内存压力告警（`performance.memory` 不可用时以 assertBudget warn 频率为信号）：`renderScale` 降 1× + 部件纹理切 @1× 目录——帧率落 30fps 容忍线（paperdoll-render §4），体验不破。

## 后果

**正向**：三档预算在最坏 bbox 口径下全部通过（cal-04-review §5）；内存有硬闸门（超阈值开发态断言）而非事后救火；试穿/切换/模式三类的内存轨迹全部封闭（无爬升路径）。

**负向与备案**
1. 双密度目录（@1x/@2x）增加资产管线一档复杂度——美术圣经 §5.5 导出口径需补两条子规格（背景类 @1×、背视图紧裁剪），**经主理人转林绘澄，本 ADR 不直接改美术圣经**（cal-04-review §6 备案）；
2. 估算口径 vs 实测可能有 ±10% 漂移——Phase 5 以 Chrome DevTools (Performance panel + `textures.getTextureKeys` 汇总) 实测复验，漂移超限走 cal-04-review §5 调节杠杆清单；
3. 预算会计依赖全项目纹理进出**必经** TexMemAccountant——列入 Phase 5 代码评审红线（绕开登记的 `this.load.image` 直接调用 → 拒绝合并，白名单仅 Boot 场景加载屏最小集）。
