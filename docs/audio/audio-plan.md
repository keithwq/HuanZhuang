## 1. 音频方向（v1 听觉身份）

- **世界观挂靠**：星夜魔法学院（D2-05）× 憧憬与梦境感（概念 §6 情绪基调）× 明亮梦幻温柔（art §0）。
- **一句话听觉身份**：*「一间洒满星光的学院晚自习」——安静、明亮、有细小魔法闪光的声音世界*。BGM 是教室窗外的夜空，SFX 是少女手边的小魔法。
- **调色板（材质域）**：水晶 / 玻璃风铃 / 钢片琴 / 丝绸织物 / 细小星尘颗粒感。全部音效落「轻、亮、短、圆润」四字诀。
- **禁用材质**：低频轰鸣、强鼓组/节拍器式打击、尖锐合成 lead、警报类上扬音、任何压迫性渐强——与美术「阴影用紫灰不用黑」同构的听觉等价物。
- **频段避让（不与 BGM 打架的总原则）**：BGM 以中低频 pad 与中频竖琴/钢琴分解为主；全部 SFX 落 1.5–5kHz 亮区且 ≤300–800ms 短促——频段与时长双重避让，无需动态闪避（ducking），契合轻量边界。

## 2. 音效设计（3 条）

### 2.1 事件清单总表

| # | 音效 | 触发 bus 事件 | 时长红线 | 包体顶 | 事件口径来源 |
|---|------|--------------|----------|--------|--------------|
| S1 | 换装轻响 `sfx_tryon` | `tryon:done`（试穿/卸下成功回调统一口径） | ≤300ms，建议 200–250ms | 5KB | architecture §4 事件链样板；paperdoll §「换装确认 ≤300ms」 |
| S2 | 套装完成叮 `sfx_setcomplete` | `outfit:setComplete`（**新事件，判据未定，见 §2.4 缺口**） | 音头 ≤300ms、总尾 ≤600ms（在动效 800ms 窗口内收束） | 15KB | art §8.1「套装完成 ≤800ms 一次性 + 轻微叮感（音频归阮和鸣）」 |
| S3 | 星尘领取音 `sfx_claim` | S04 余额变更事件，过滤 `delta>0 ∧ reason ∈ {daily_task, achievement, milestone}` | ≤300ms | 10KB | daily §2.5 / economy 领取流 / hud「余额变更事件刷新货币栏」 |

### 2.2 逐条设计

**S1 换装轻响（sfx_tryon）**
- **音色方向**：丝绸轻抚起音（≤80ms 的高频柔顺摩擦感，像指尖抚过缎面）+ 一粒极小的玻璃泛音收尾（像别针落定的「嗒」，但圆润不脆硬）。整体印象 = *布料拂过 + 细针别好*，音区偏高（约 2–4kHz 主体），无低频成分。
- **时长**：200–250ms（动效旧件淡出 100ms + 新件淡入 150ms 全程内完成，音尾不拖过动效）。
- **克制纪律**：本项目**最高频触发**的音效（试穿是核心循环本体，概念 §2.4「可无限循环」），三重防疲劳——
  1. 音量为三条中最低（相对音量 0.35，见 §4.3 音量表）；
  2. 设计上选择「极易被忽略但缺失可感」的响度，参考纸页翻动的存在感；
  3. **运行时微变奏**：每次播放随机 `detune ±30 cents`（Phaser Sound 原生支持，零额外资产、零包体）——同一文件听感自然抖动，杜绝机械复读感。
- **边界**：`tryon:done` 在 S06 批量回穿（applyLook 13 槽连发）时会产生连响——音频层须做 **300ms 合并窗**：窗口内多次到达只播一次（§4.4 播放纪律 P-2）。

**S2 套装完成叮（sfx_setcomplete）**
- **音色方向**：水晶风铃小琶音——两到三粒上行音（如 宫→徵→高八度宫 的明亮三音型），材质感介于玻璃与金属之间偏玻璃，尾端带极轻的「星尘洒落」细粒衰减感（高频微噪声柔化收尾，非白噪「嘶」感）。音区中高，无任何低频支撑，避免与庄重/完成感常见的铜管式厚重冲突——本作的「完成」是少女摘下星星别在发间的轻快，不是勋章授予。
- **时长**：音头（琶音两粒）≤300ms 与动效光晕呼吸起点同步；星尘尾在 ≤600ms 内收束，完整落进动效 800ms 窗口（art §8.1）。
- **克制纪律**：三条中最显著但仍克制（相对音量 0.6）；**与 S1 互斥**——套装由「换上最后一件」达成时，S1 与 S2 同刻到达，音频层抑制当次 S1 只播 S2（一次点按一次声音，§4.4 P-3）。
- **触发判据缺口（重要）**：「什么算套装完成」在 8 册 GDD 与架构文档中均未定义（art §8.1 只定义了表现层）。候选口径：*同系列（economy §3 系列/风格标签字段）部件在对应槽位同时全部上身*。**判据语义归文策渊补 GDD 口径，事件名与发射点归程基岩落位**（见 §8.1）。

**S3 星尘领取音（sfx_claim）**
- **音色方向**：一粒温润小铃（比 S2 更圆润更小，像瓷风铃而非水晶）+ 极轻的向上拂动感（短促柔和的频率上扬衬托「星尘飞入货币栏」动效，daily §2.5）。避免「金币叮当」的俗成赌场感——货币名是**星尘**（D3-07），音色按星尘意象走柔亮而非金属钱币。
- **时长**：≤300ms，与「星尘飞入货币栏 ≤300ms 家族」动效同步。
- **克制纪律**：相对音量 0.5；**触发过滤**：只挂发放不挂消费——购入（spendCoins，delta<0）不响；里程碑自动发放（milestones：每 +3 件 60 星尘）与成就/任务领取同曲（同为奖励时刻，不细分，守三条边界）。三连领取（daily §8 竞态用例：三张卡同刻达标逐张领取）时 3 次点按播 3 次，属正常操作节奏，不做额外节流。

## 3. BGM 1 首（bgm_main）

### 3.1 基调

星夜魔法学院×憧憬梦境感：**安静夜空下的温柔魔法感**——不空灵到失温（避免「幽冥/飘渺」歧义，守住 art §0 明亮梦幻），不甜腻到儿童玩具感。情绪坐标 = *晚风 + 远处钟楼 + 一抬头满天星*。

- **乐器方向**（材质描述，非参考曲名）：竖琴或柔钢琴做分解和弦骨架；钢片琴/水晶铃类打点做主奏旋律（与 SFX 调色板同族，听觉身份统一）；柔弦/合成 pad 铺底；偶发高频小铃点缀作「星星闪烁」 nonce，密度低（每乐句 ≤1 次）。
- **调性/速度**：大调（可带一点 Lydian 色彩营造「仰望」感）；≈72 BPM；无鼓组或仅极轻的心跳式低频脉动（可选项，v1 建议直接无鼓）。
- **编排密度**：中低。单局 3-8 分钟（P3）+ 高频进出，玩家单次会话会把循环听 3-8 遍——**无强记忆 hook**、无大动态起伏（最大段落落差 ≤3dB），靠织体呼吸维持趣味而非旋律抓耳。

### 3.2 结构与循环

- **循环长度**：60–72 秒（约 16+16+16+8 小节的 A–A′–B–A″ 单循环）。短于 45s 单位时间内重复感过强，长于 90s 则逼近包体红线（见 §5.2）。
- **无缝循环设计（mp3 关键约束）**：mp3 编码器首尾 padding 会导致循环接缝，**不依赖播放器级 gapless**，用编曲手段消化——
  1. 循环点选在**长 pad 音持续跨越处**（pad 从 B 段末延续进 A 段头，接缝被持续音掩蔽）；
  2. A 段入口不设打击性起音（无鼓 = 无「突然一击」暴露接缝）；
  3. 混音保证循环点两侧响度/频谱一致（首尾帧对齐）。
- **首尾即入口（重进不刺耳）**：页面刷新/重进时 BGM 从头播——A 段头 2 小节**只留 pad+竖琴**，主奏钢片琴约 5 秒后才进。任何时刻切入听感都是「渐入氛围」，无冷启动刺耳。

### 3.3 淡入淡出与生命周期

| 场景 | 处理 |
|---|---|
| 首次启动 | 解锁（§4.1）+ 加载完成（§5.3）后 **1.5s 淡入**，从 0 到目标音量 |
| 切后台 `visibilitychange → hidden` | **立即静音/暂停**（与 ADR-002 三钩子同源；Web Audio 在后台标签页可能继续出声，须主动处理） |
| 回前台 `→ visible` | **1s 淡入恢复**，从暂停点续播（不从头来，保护「我的小世界一直在」的持续感，P3 零压力回归） |
| 关页 / `pagehide` | 无需淡出（正在被销毁，静默即可） |
| 会话内反复进出覆盖层/模式切换 | **不做任何 BGM 处理**——商店/房间/衣柜切换 BGM 恒定（单曲目边界，D4-01），零动态混音复杂度 |

### 3.4 防疲劳设计（对「单局 3-8 分钟高频进出」的友好）

1. 响度定位为**背景**：integrated ≈ -20 LUFS（响度感为「环境」而非「作品」），与 SFX 频段避让（§1）共同保证听 8 分钟不累。
2. **音量恒定律**：v1 无情绪分层（不做商店变奏/深夜变奏等）——单首恒定是 D4-01 边界，任何「场景变奏」诉求一律进 v1.1 候选，不在本方案偷跑。

## 4. 音频实现策略（Phaser 3.88）

### 4.1 Web Audio 解锁时机（移动浏览器硬约束）

移动浏览器策略：AudioContext 必须在**用户首次交互**后才可出声（iOS Safari 最严格，微信 XWeb 同样受限，架构 §9 支持矩阵全中）。接入口径：

1. **保留 Phaser 默认 `autoUnlock: true`**（SoundManager 首次 pointerdown/touchstart 时 resume AudioContext），不自行造解锁机制；
2. **显式兜底**：BootScene `create` 时注册一次性 `this.input.once('pointerdown')` → `this.sound.unlock()`，覆盖个别 WebView 事件吞噬场景；
3. **解锁前行为**：SFX 解锁前自然无声（首个交互本身来不及出声，可接受——首次交互多为「进入游戏」类点按，不承载反馈语义）；BGM 等 `sound.once('unlocked')` 事件后才启动淡入；
4. **禁用「假解锁」**（如读屏器用户可能无 pointer 事件的极端情形 v1 不做特殊路径——触屏唯一输入 D0，风险不成立）。

### 4.2 事件挂钩清单（对照 architecture §4 事件链）

| 音效 | 监听 | 发射方现状 | 备注 |
|---|---|---|---|
| S1 | `bus.on('tryon:done')` | ✅ 架构 §4 样板已含此事件 | 含 unequip（卸下也是试穿反馈家族）；受 300ms 合并窗（P-2） |
| S2 | `bus.on('outfit:setComplete')` | ⚠️ **新事件，全链路未定义** | 发射点建议在 paperdoll compositor 换层成功后做系列判定；判据归文策渊（§8.1） |
| S3 | S04 余额变更事件 | ⚠️ hud 册以「S04 余额变更事件刷新货币栏」语义引用，**事件名未在架构落字** | 建议命名 `coins:changed`，音频层过滤 `delta>0 ∧ reason ∈ {daily_task, achievement, milestone}`（§2.2-S3） |
| BGM | 无业务事件 | —— | 生命周期挂 `visibilitychange`（§3.3），与 ADR-002 存档冲刷共用钩子、互不干扰 |

命名遵循 bus 现有 `域:动作` 风格（`tryon:done` / `stat:tryOn` 同族）。**三个待定名（outfit:setComplete / coins:changed / 以及音频层自身的 `settings:audioChanged`）统一经主理人与程基岩对齐后落位，本方案命名均为提案**（§8.2-3）。

### 4.3 音量结构（两「软总线」）

Phaser 无混音总线，用**常量表虚拟总线**实现（`src/core/constants/audio.ts`，入 constants 纪律，架构 §4 通信纪律 5）：

| 层 | 常量 | 值（提案，Phase 5 真机校准） |
|---|---|---|
| BGM 音量 | `VOL_BGM` | 0.55 |
| S1 tryon | `VOL_SFX_TRYON` | 0.35（三条中最低） |
| S2 setcomplete | `VOL_SFX_SETCOMPLETE` | 0.60 |
| S3 claim | `VOL_SFX_CLAIM` | 0.50 |
| 全局开关 | `settings.audioEnabled` | true（见 §6/§7）——实现为 SoundManager mute，非逐音量清零（保留各音量常量单一事实） |

不做压限器/闪避/滤波——频段+响度预规划（§1/§3.4）替代动态混音，守 D4-01 轻量边界。

### 4.4 播放纪律（音频层内置 guard，实现于 `src/systems/audio/` 或 ui 侧轻服务，归程基岩定）

- **P-1 单实例**：同名 SFX 在播未完时新到达 → 重触发（打断重播，Phaser 默认行为，与动效「新事件到达即中止」同构，paperdoll §换装确认口径）。
- **P-2 合并窗**：300ms 窗口内同键多次事件 → 播一次（覆盖 S06 批量回穿 13 连发与极端快速点选）。
- **P-3 优先级互斥**：S2 与 S1 同刻 → 只播 S2（一次点按一次声音）。
- **P-4 随机 detune**：S1 每次播放 detune ±30 cents（§2.2-S1）。

### 4.5 内存说明（不入 CAL-04，单列备案）

音频解码后常驻 **Web Audio 缓冲区，不计入 ADR-003 纹理预算**（CAL-04 只管纹理）：BGM 60s @44.1kHz 立体声解码后 ≈21MB（float32），SFX 合计 <1MB。建议：**BGM 源文件用 32–44.1kHz 采样率**交付（柔化 pad 素材对采样率不敏感），解码后 ≈15MB 量级，整机内存影响可忽略；此数值由程基岩在 Phase 5 真机压测时随 CAL-04 一并留证据，不新增 CAL 条目。

## 5. 格式与包体

### 5.1 格式取舍：**单一 mp3**

| 格式 | iOS Safari 15+ | Android Chrome 90+ | 微信 X5/XWeb | 结论 |
|---|---|---|---|---|
| mp3 | ✅ | ✅ | ✅ | **唯一全矩阵通用格式，v1 取它** |
| ogg/vorbis | ❌ | ✅ | ✅ | iOS 全线不支持，双格式意味着 iOS 侧兜底文件必存在——放弃 |
| m4a/aac | ✅ | ✅ | ⚠️ 个别 WebView MIME 异常史 | 备而不选 |

取舍代价（如实声明）：mp3 循环接缝 padding → 已用 §3.2 编曲手段消化，不赌运行时 gapless。**可选备案**（Phase 5 与程基岩合议，非本方案默认）：Phaser Loader 支持多 URL 降级，可加 ogg 副本（Android/微信走 ogg 接缝更干净）——代价是仓库体积 +1 份 BGM、运行时单设备仍只下载一种格式，**不破 500KB 用户下载预算**。v1 默认不启用。

### 5.2 包体预估（红线 ≤500KB）

| 文件 | 内容 | 规格 | 预估 |
|---|---|---|---|
| `hz_sfx_tryon_v01.mp3` | 换装轻响 0.25s | 128kbps mono mp3 | ≈4KB |
| `hz_sfx_setcomplete_v01.mp3` | 套装完成叮 0.6s | 128kbps mono mp3 | ≈10KB |
| `hz_sfx_claim_v01.mp3` | 星尘领取音 0.3s | 128kbps mono mp3 | ≈5KB |
| `hz_bgm_main_v01.mp3` | BGM 60–72s | 48kbps joint-stereo mp3 | **≤420KB 硬顶**（60s ≈360KB、72s ≈432KB 超顶则回到 60s 或降 40kbps） |
| **合计** | | | **≤ 439KB ≤ 500KB ✅（余量 ≥61KB）** |

> SFX 用 128kbps（短文件高码率近乎免费，保高频细节）；BGM 48kbps 是本方案的**关键压缩决策**：柔化 pad+钢片琴素材在该码率可接受（无瞬态打击素材），若 Phase 5 试听发现高频颗粒感，优先缩循环到 60s 内保码率 ≥56kbps，次选降采样，**不破 420KB 单文件顶与 500KB 总红线**。48kbps 对 mp3 是质量下限附近，已如实标注为「混音师验收项」（§8.3 用户审批项 4）。
> 命名约定：`hz_{sfx|bgm}_{名}_{v两位}.mp3`，与资产指纹文件名 + immutable 长缓存策略（架构 §9）天然兼容。

### 5.3 加载策略

| 资产 | 时机 | 理由 |
|---|---|---|
| 3 条 SFX（合计 ≈19KB） | **PreloadScene 随 UI 底图加载**（一次性） | 体积可忽略；保证玩家第一次点选试穿（首个核心交互）就有声 |
| BGM（≈360–420KB） | **延迟加载**：PreloadScene 完成、StageScene 就绪后，空闲时段独立 loader 拉取 | 不阻塞首屏可玩（P1 所见即所得优先级最高）；加载完成且已解锁 → 1.5s 淡入（§3.3）；未解锁则等首个交互 |
| 网络差兜底 | BGM 加载失败 → **静默放弃本会话 BGM**，SFX 照常，无重试无报错弹窗 | BGM 是氛围件非功能件；重试/报错均违背 P3 轻量与摆弄无打断原则 |

## 6. 减敏与静音边界（正交声明）

- **`prefers-reduced-motion` 只管视觉**（art §9.4 / accessibility M3）：关 3 项常驻微动效、反馈降级 ≤100ms 淡切、套装完成降级**静态光效帧+文字**。**音频不在其管辖内**——减敏模式下 S1/S3 照常播放；S2 随套装完成降级仍播（静态帧+文字+叮，无动效不等于无声）。
- **`settings.audioEnabled` 独立管听觉**：布尔总开关，SFX+BGM 同开同关（v1 不做分轨开关——克制边界）；关 = SoundManager 全局 mute，BGM 暂停而非仅音量 0（省解码后缓冲的持续出声与电量）。
- **默认值：开（true）**。依据：① 音频默认存在是网页小游戏常规预期，静音属用户主动选择；② 听觉身份是「憧憬梦境感」的构成要素（概念 §6），默认关等于自废方向；③ 未成年向无强制静音的合规诉求（对比：有背景音乐的休闲产品惯例即默认开）。
- 两开关**正交组合全表**：动效关+音频开 ✅；动效开+音频关 ✅；双关 ✅；双开 ✅。任一组合均合法状态，无联动逻辑。

## 7. 需存档侧配合清单（经主理人转程基岩，落 ADR-002 settings 补丁）

当前 S04 `settings` 仅有 `reducedMotionOverride`（local-save §档结构）。新增：

| 键 | 类型 | 默认值 | 语义 |
|---|---|---|---|
| `settings.audioEnabled` | boolean | `true` | 全局音频总开关（SFX+BGM 同控）；`true`=开 / `false`=全局静音。无 `null` 跟随态（浏览器无系统级「全局音频关」媒体特性可跟随，`prefers-reduced-motion` 的三态模式不适用） |

- **兼容模式**：旧档缺失该键 → Serializer 按默认 `true` 补齐，零迁移（直接套用 ADR-002 §4 已推广的「新字段必须可派生或可默认」模式，无 schemaVersion 变更）。
- **写入时机**：设置切换属低频操作，归入「即时写」清单（WritePolicy 硬编码清单顺手加一行）。
- **开关 UI 入口**：v1 需一个可触达入口（建议 S05 hud 顶导或覆盖层一角，小喇叭 icon 二态）。**入口的 UI 归属与文案口径归文策渊定（§8.1-2）**，存档键归程基岩。
- 音频层监听 `settings:audioChanged`（命名提案）即时生效 mute/恢复，无需刷新。
