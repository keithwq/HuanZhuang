## 1. 系统清单

| ID | 系统 | 职责边界（一句话） | 垂直切片最小集 | 优先级 |
|----|------|--------------------|:---:|:---:|
| S01 | **纸娃娃分层渲染** | 13 槽位（D1-10）分层叠加合成角色画面，槽位互斥、层内换装，是所有"看得见"的地基 | ✅ | **P0** |

| S03 | **衣柜与试穿交互** | 服装单品（40-50 件，D2-02）的网格浏览、风格标签筛选、点选试穿（点选即换、所见即所得 P1） | ✅ | **P0** |
| S04 | **本地存档（localStorage）** | 持有单品、家具摆放、货币、造型收藏、成就/任务进度的持久化与版本迁移（D1-13：无云存档，Phase 5 复评丢档风险） | ✅ | **P0** |
| S05 | **主界面 HUD** | 竖屏 9:16 主界面：上 2/3 角色台/房间舞台、底部抽屉（衣柜⇄家具切换）、货币栏、任务/商店/成就入口 | ✅ | **P0** |
| S06 | **造型保存** | "我的造型"收藏（3-5 位）读取当前 13 槽装扮快照、命名、一键回穿 | ✅ | P1 |
| S07 | **房间装饰（锚点版）** | 1 房间、约 30 件家具（D2-03）、锚点网格吸附摆放、2D 正面视角 + 地面 Y 排序、720×1280 单屏（D2-04）、氛围光随摆放进度点亮 | ❌（v1 第二波） | P1 |
| S08 | **货币与商店** | 1 种货币的收支账本 + 商店直购流（浏览→购入→即时入柜）（D1-04） | ✅（简版：购买流） | P1 |
| S09 | **轻量每日任务** | 每日 2-3 个软任务轮换（无倒计时、无强评分，D1-03），本地日期翻转刷新，完成发小额货币 | ❌（v1 第二波） | P2 |
| S10 | **成就解锁** | 成就清单定义、进度追踪、达成直接解锁单品/家具（D1-04 双轨之解锁轨） | ❌（v1 第二波） | P2 |

## 2. 依赖关系

**阅读方式**：箭头 A → B 表示"A 阻塞 B"（B 依赖 A 先定/先建）。

```
S01 纸娃娃分层渲染 ──→ S02 双视图切换 ──→ S06 造型保存（读快照）
   │                        │
   │                        └──→ S05 HUD（角色台舞台位）
   ├──→ S03 衣柜试穿 ──→ S06 造型保存
   │        │      └────→ S08 货币商店（购入入柜事件）
   │        └────────────→ S09 每日任务（试穿计数事件）
   │                     └→ S10 成就解锁（图鉴/试穿事件）
   │
   └──→ S05 HUD（舞台渲染容器）

S04 本地存档 ──→ S03（持有状态） S06（造型持久化） S07（家具摆放）
            ──→ S08（货币账本） S09（任务进度/日期翻转） S10（成就进度）

S07 房间装饰 ──→ 依赖 S04（摆放持久化）+ S05（复用底部抽屉 UI 范式）+ S10（家具解锁来源）
S05 HUD ──→ 作为容器依赖 S01/S07 的舞台渲染；被 S08/S09/S10 依赖（入口页挂载）
```

**关键结论**：
1. **S01 + S04 是双地基**：S01 阻塞全部"看得见"的系统，S04 阻塞全部"记得住"的系统——这两者先定稿，全链路才稳。
2. **S07（房间）依赖面最窄**（仅 S04/S05/S10），且交互复用 S03 的抽屉范式，是"第二波"中风险最低的。
3. **S08/S09/S10 相互只通过"货币/物品发放"弱耦合**，可并行设计，但需 S04 先定账本数据结构。

## 3. 实现优先级排序（含理由）

| 序 | 系统 | 排序理由 |
|----|------|----------|
| 1 | S01 纸娃娃分层渲染 | 最高风险骨架：13 槽 z 序、D2-01 双视图懒加载、3.5 头身分层图对位全部在此定生死，任何下游错误都代价最大 |
| 2 | S02 正/背双视图切换 | 与 S01 同生共死（同属渲染骨架），翻转过渡 ≤300ms 是体验红线（P1） |
| 3 | S04 本地存档 | 数据地基：被 7 个系统依赖，账本/持有/进度的字段口径不先定，S03 之后的系统全在流沙上写 |
| 4 | S03 衣柜与试穿交互 | 核心玩法本体（试穿即玩法），依赖 S01/S04，尽早让"点选→变装"的垂直切片可玩 |
| 5 | S05 主界面 HUD | 容器性质，与 S03 并行细化，让切片有完整观感 |
| 6 | S06 造型保存 | 依赖少（S01/S03/S04），补齐核心循环"作品感"闭环 |
| 7 | S07 房间装饰 | 第二表达画布，锚点版已定稿（D2-03/04），复用 UI 范式，第二波首个 |
| 8 | S08 货币与商店 | 经济循环主源（D1-04 直购轨），需 S04 账本稳定 |
| 9 | S09 轻量每日任务 | 货币供给侧（D1-03），依赖 S08 发奖与 S03 事件，P3 红线（无倒计时）在此把关 |
| 10 | S10 成就解锁 | 依赖事件最全（S03/S07/S08 全部事件），收尾件；解锁发放口径已定（直接给物品，D1-04） |

## 4. GDD 生产顺序计划

八节 GDD 按"依赖 × 风险"排序，**首批 3 册**：

| 批次 | GDD | 八节中的预计难点 |
|------|-----|------------------|
| **第一批（骨架，建议立即开工）** | **① S01 纸娃娃分层渲染 + S02 双视图切换**（合并为一册：`paperdoll-render.md`） | 13 槽 z 序表、双视图切换的懒加载触发与内存上限（D2-01 背面 60% 精度口径）、槽位互斥/连体衣拆槽等边缘情况 |
| | **② S04 本地存档**（`local-save.md`） | 账本/持有/进度的数据结构（被 7 系统引用）、localStorage 容量边界、存档版本迁移策略 |
| | **③ S03 衣柜与试穿交互**（`wardrobe-tryon.md`） | 点选即换的 UI 状态机、风格标签筛选、双视图下图衣同步刷新 |
| 第二批 | ④ S05 HUD → ⑤ S06 造型保存 | HUD 布局规格与槽位图标流；快照数据格式 |
| 第三批 | ⑥ S07 房间装饰 → ⑦ S08 货币与商店 | 锚点点位表与 Y 排序规则；定价与收支平衡公式 |
| 第四批（收尾） | ⑧ S09 每日任务 → ⑨ S10 成就解锁 | 任务池轮换规则；成就触发事件清单 |

**建议派发节奏**：第一批 3 册先行（可并行撰写，互相引用处已在上文依赖图锁定）；第一批过评审后第二、三批流水展开；每册完成即回传主理人走设计评审门，不攒批。

## 5. 需用户拍板清单（本文档新产生的边界判断，未写成默认）

| # | 事项 | 选项与建议 | 说明 |
|---|------|-------------|------|
| UQ1 | **GDD 分册口径**：①「S01+S02 合并为一册」是否认可？（渲染与双视图资产/渲染管线同源，拆两册会大量互相引用）②「S08 货币商店 + S10 成就解锁」是否合并为「获取与经济」一册？（经济平衡需同册评审，D1-04 双轨天然一体） | 建议均合并 → 全部 GDD 从 10 册收敛为 **8 册** | 影响后续派发的任务粒度 |
| UQ2 | **造型收藏位具体数量**：概念 v1.0 定"3-5 位"，写 S06 GDD 前需定死 | 建议 **4 位**（大于最少起步值 3，留余量；不做扩容内购，D2-06） | 字段进 S04 存档结构 |
| UQ3 | **商店上新节奏**（S08 GDD 前需口径）：v1 内一次性全量上架，还是按日/周解锁式上新制造回访拉力？ | 建议**周更节奏**（每周 2-3 件，配合 P3 轻量回归）；一次性上架则收集压力前置、后期无拉力 | 概念 §4"为什么再来"提及商店上新，此处需定形 |
