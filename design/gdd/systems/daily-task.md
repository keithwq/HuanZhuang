## 1. 概述

每日 3 条软任务：无倒计时、无强评分、不指挥玩家搭什么（D1-03）——任务是"今天摸一摸游戏"的轻推，完成后玩家回到自由摆弄（概念 §2.2）。单条奖励 150 星尘、日均 450（D3-06 冻结），构成经济供给侧主源（economy §4.3）。

## 2. 机制

### 2.1 任务结构

- 每日固定 **3 条**（概念 §2.1「2-3 个」上限取 3，economy §4.3 已声明）；
- 单条奖励 **150 星尘**（D3-06），领取即 `addCoins(150, 'daily_task')` 即时写盘；
- 判据全部基于 S04.stats **当日增量**：bumpStat 推进事件到达时，匹配当日任务的 `progress += n`——当日性由任务清单随日期翻转重建天然保证，**不引入第二套计数器**（判据源唯一红线）。

### 2.2 任务池（11 条草案 · 静态配置不入档，local-save §4 口径）

| # | 类别槽 | 条目文案（轻推语气基调） | 判据（stats 键 · 当日增量） |
|---|---|---|---|
| 1 | A 试穿 | "让角色换换心情：试穿 5 件单品" | tryOnTotal ≥ 5 |
| 2 | A 试穿 | "今天格外想打扮：试穿 12 件单品" | tryOnTotal ≥ 12 |
| 3 | A 试穿 | "摆弄到停不下来：试穿 20 件单品" | tryOnTotal ≥ 20 |
| 4 | A 试穿 | "试穿 2 件从没上过身的新单品" | tryOnUnique ≥ 2 |
| 5 | A 试穿 | "衣柜里还有没试过的：新试 4 件单品" | tryOnUnique ≥ 4 |
| 6 | B 保存 | "把今天的搭配存进九宫格：保存 1 个造型" | lookSavedTotal ≥ 1 |
| 7 | B 保存 | "收集自己的灵感：保存 2 个造型" | lookSavedTotal ≥ 2 |
| 8 | B 收藏 | "从商店带回 1 件新单品" | itemsOwnedTotal ≥ 1 |
| 9 | B 收藏 | "今天想收点什么：带回 2 件新单品" | itemsOwnedTotal ≥ 2 |
| 10 | C 摆放 | "给小屋换个新气象：摆放 1 次家具" | furniturePlacedTotal ≥ 1 |
| 11 | C 摆放 | "重新布置房间吧：摆放 3 次家具（换位置也算）" | furniturePlacedTotal ≥ 3 |

- **文案纪律**（§9.6 语气基调）：全部为邀请式动词 + 数量；**禁止**倒计时话术（"仅限今天""错过不再"）、禁止损失话术（"别错过奖励"）、禁止指挥审美（"搭配一套正确风格"——D1-03 红线）。
- 条目 8/9 判据说明：itemsOwnedTotal 覆盖购入与成就解锁两轨（addItem 唯一入口统一 bump，local-save §6），文案用中性"带回"不区分获取方式。

### 2.3 每日抽取规则（本册定稿）

**三槽位制 + 槽内随机 + 可达性校验**：

```
槽 A（试穿类，池 #1~5）抽 1 条
槽 B（保存/收藏类，池 #6~9）抽 1 条
槽 C（摆放类，池 #10~11）抽 1 条
任一槽不可达 → 从"全部可达池"随机补足 1 条（同日不与已抽条目重复）
```

- **可达性校验**：条目进入当日候选的前提 = 判据当日可达成（如摆放类要求 `ownedFurniture ≥ 1`、新试类要求存在未试穿拥有件、保存类恒可达）——**杜绝死任务**（新玩家无家具却抽到"摆放 3 次"即挫败）。
- 定稿理由：①三槽保证每日引导覆盖换装+房间双画布（房间引导不因随机缺席，呼应 D1-05 房间第二核心定位）；②槽内随机保新鲜感；③同条允许连续两日出现（池小，强制跨日去重会三日内穷尽槽位，复杂度不值收益——D3-04 工程量最省精神同源）；④可达性校验守住 P3 零挫败。

### 2.4 日期翻转联动（local-save §2.3 冻结，D3-04 不设防）

- 回前台/打开时比对 `daily.dateKey`：不等即翻转——任务清单**重新抽取**、progress 清零、claimed 重置；
- **跨日未完成自然过期不发奖**（无补偿、无"昨日遗憾"提示——轻量基调，未完成不构成损失感）；
- 翻转采用**事件驱动惰性判定**：任何 bumpStat / addCoins 到达时先验 dateKey，过期则先执行翻转再处理事件——完成动作发生在 23:59:59 的极端情形按到达顺序归属，≤1 条误差不做补偿（轻量化，不为此加时间戳机制）。

### 2.5 领取流与闭环呼应

```
[任务卡: 文案 + 进度条(progress/goal)] progress ≥ goal → 卡片转可领取态（星紫描边 + 领取按钮亮起）
   └ 点[领取 150] → addCoins → 进度条定格 + 星尘飞入货币栏动效（≤300ms 家族）→ claimed
```
- **逐张领取、不做"一键全领"**：3 次点按符合摆弄节奏，且省一个全局按钮的阅读成本（§9.6）。
- 闭环呼应（本册定义）：economy §2.1 余额不足文案"星尘不够啦，去做每日任务吧"——**不设跳转按钮**（覆盖层单层原则，hud §5.4：商店开着不能再叠任务页），改用**顶导任务入口角标常显**承接引导：完成未领取数 > 0 时角标常亮，玩家关掉商店自然看到；本册验收含该呼应链走查。

## 4. 公式

- **抽取**：`当日 3 条 = 抽(槽A可达池) ∪ 抽(槽B可达池) ∪ 抽(槽C可达池)`，任一空槽 → `从(全可达池 − 已抽条目) 随机补足`；随机源为本地 Math.random（无服务器、无防重，D3-04 同精神）。
- **进度条**：`显示进度 = min(progress, goal) / goal`，达标定格满格；claimed 后按钮转"已完成"灰态。
- **可达性判定**（槽 C 示例）：`可达 ⇔ S04.ownedFurniture.length ≥ 1`；新试类：`存在 ownedItems 中 tryOnUnique 未覆盖件 ⇔ itemsOwnedTotal > 试穿过件数`；保存类恒可达（造型保存无前提）。
- **日均供给对账**：`3 × 150 = 450 星尘/日`（D3-06 B 档口径）——与 economy §4.4 集齐天数公式分子分母一致，本册不得改动任何一侧。
- **领奖动效**：星尘飞入 ≤300ms（美术圣经 §8.1 反馈家族）、一次性、减敏降 100ms 淡切。

## 5. 边缘情况（≥5 类）

1. **完成与翻转竞态**（§2.4 惰性判定）：23:59:59 完成第 N 次试穿、事件处理时已跨日 → 先翻转（旧任务过期作废）→ 该次试穿计入新一日任务候选池的 progress 起点——**事件不丢弃、不双计**；≤1 条任务的归属误差接受、不补偿。
2. **三连完成瞬时领奖**：三张卡同刻达标 → 各自独立领取（无批次锁）；连续三次 addCoins 各即时写盘（local-save §2.2 关键操作即时写），中断（如翻转插队）时已领取部分已落账、未领取部分随过期作废——账本任何时刻无中间态。
3. **任务判据跨系统事件就绪顺序**：S09 是纯消费方（监听 bumpStat），S01/S03/S06/S07 事件源已在第一~三批冻结——无循环依赖；本册上线联调顺序：S04 判据源就绪 → S09 挂监听 → hud 角标通路，三方缺一不进入验收。
4. **首启当日任务初始化**：新档创建即抽取当日 3 条（可达性校验下首启通常 = 槽 A×1 + 槽 B×2，槽 C 不可达回退）；新档默认套装保证试穿/保存类天然可玩（paperdoll §5.5 同源）。
5. **判据与里程碑不重叠**（economy §5.6 红线同源核查）：任务判据 = stats **当日增量**（行为窗口），里程碑 = stats **累计值**（收藏进度）——同键（itemsOwnedTotal）但**窗口正交**，非"同一进度两处发奖"红线场景；红线逐条复核结论：11 条任务无任何一条直接复用 economy 里程碑阈值（3 件累计）或成就判据阈值（economy/room 冻结值）。
6. **改时间刷任务**（D3-04 明示接受）：本地时钟回拨/前跳均按 dateKey 不等即翻转处理，可刷；**不设防、不视为缺陷**（无付费随机、无套利价值）。
7. **领取瞬间切换模式/打开覆盖层**：addCoins 即时原子完成，任何切换不吞奖励；任务页自身为覆盖层，领取中收到 openOverlay 其他页请求 → 按 hud 单层原则排队拒绝（hud §5.4 口径），本页关闭后生效。

## 8. 验收标准

1. 每日恰 3 条、三槽位分布正确、可达性校验零死任务（构造"零家具新档"用例：槽 C 回退路径命中）。
2. 单条领取入账 150 星尘、日均合计 450 与 D3-06 对账一致；全部领取路径 addCoins 唯一、reason='daily_task' 入 ledger 可查。
3. 翻转重置正确：任务重抽、进度清零、claimed 重置、跨日未完成不发奖；改时间可刷不视为缺陷（D3-04）。
4. 判据推进实时（试穿第 N 次的当帧即见进度条 +1）；角标 = 完成未领取数，领取后即时清减。
5. 文案走查：11 条全部邀请式语气，零倒计时/损失/指挥话术（§9.6、D1-03 双红线）。
6. 竞态用例：23:59:59 完成事件、三连瞬时领取、领取中开覆盖层——账本无中间态、无重复入账、无吞奖。
7. 红线复核留痕：任务阈值 vs 里程碑（+3 累计）vs 成就冻结值（economy §2.2/room §2.5）三组数字逐一不等，记录在验收报告。
8. 余额不足引导链闭环：商店 toast 文案 → 玩家关店 → 顶导任务角标常显（hud 验收联动项）。

## 9. 需用户拍板清单

**无**——奖励值 150/条（D3-06 已拍板）、任务量 3 条（概念既定上限）、抽取规则三槽位制与 11 条池为本册职责内定稿（理由见 §2.3）。若用户希望任务数量/类别配比调整（如"3 条全随机不分类"或"每日 2 条"），属产品级参数变更，走决策记录重新拍板。
