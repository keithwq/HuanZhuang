# HuanZhuang 可访问性分级矩阵（Accessibility Feature Matrix）

> 版本：v1.1 · Phase 3 · 2026-11-21（v1.0 → v1.1：GAP-4/C3 由 ux-spec.md §2 定稿闭环，矩阵状态同步）
> 作者：林绘澄（美术总监）· 主理人游承峰调度（P3-AD-006 并行线 B）
> 输入基线：美术圣经 v0.5 §9 可访问性基线（含 §9.6 未成年专项）、§3.2 字号层级、§6 UI 风格、§8 动效原则；决策记录 D1-02（12-16 岁未成年女性）、D1-11（动效白名单）、D2-06/D3-03（免费无内购/一次性上架）
> 用途：**Phase 4 预制作排期依据 + Phase 5 验收门槛参照**；UX 规格（文策渊产）与 HUD/各系统 GDD 须引用本矩阵分级，不得低于 v1 目标档。

---

## 1. 三级分档定义

| 档位 | 定义 | 裁定规则 |
|---|---|---|
| **Basic（最低合规线）** | 缺失即不可用或不安全的硬底线：对比度、触控目标、光敏安全、文本兜底、反馈可读 | v1 任何切片上线**必须 100% 达标**，无豁免通道 |
| **Standard（v1 目标档）** | 让目标人群（12-16 岁，D1-02）舒适、无障碍地完成全部玩法的体验线：减敏、色弱双通道、单手可达、认知减负、未成年情绪/商业化安全 | **v1 验收门槛 = Standard 全项通过**；单特性延期须回主理人走决策记录 |
| **Comprehensive（远期档）** | 超出目标人群普遍需求的增强线：高对比模式、文本缩放、可调字号、校验流程化 | v1.1+ 候选，**不阻塞 v1**，逐项走 decisions.md 决策通道排期 |

## 2. 逐特性矩阵

标注说明：**归属档位** = 该特性所属最低档；**v1 落位** = 规格锁定（美术圣经已定义）/ 待实现（规格有、需引擎或资产落地）；**成本** = 低（纯规格/资产内）/ 中（跨系统）/ 高（结构性）。

### 2.1 视觉域

| # | 特性 | 归属档位 | v1 落位 | 成本 | 规格落点 |
|---|---|---|---|---|---|
| V1 | 正文对比度 ≥ 4.5:1（WCAG AA），色值已验算（夜墨/墨夜系） | Basic | 规格锁定 | 低 | 圣经 §9.1 |
| V2 | 大字号(H1/H2)与图形对比 ≥ 3:1 | Basic | 规格锁定 | 低 | 圣经 §9.1 |
| V3 | 语义色文字化使用一律按 ≥ 4.5:1 校验 | Basic | 规格锁定 | 低 | 圣经 §9.1 |
| V4 | 状态双通道：颜色永不单独承载信息（已拥有/未解锁/稀有度须叠加角标或描边差异） | Standard | 规格锁定 → **待实现**（UI 资产生产时落位，Phase 4） | 低 | 圣经 §9.2 |

## 3. v1 = Standard 档达标缺口清单（Phase 4/5 引用）

**结论：规格级缺口为零**——Standard 档全部 14 项特性规格已在美术圣经 v0.5 锁定；剩余为**实现级待办 4 项**：

| 缺口 | 责任侧 | 建议排期 | 成本 |
|---|---|---|---|
| GAP-1 `prefers-reduced-motion` 引擎接入（M3） | 程基岩（Phase 3 技术搭建并入） | Phase 3 → Phase 5 验收项 | 中 |
| GAP-2 「转身」按钮 UI 资产 + 摆放模式点位提示等价路径（T3） | 美术（Phase 4 P0 UI 资产包） | Phase 4 | 低 |
| GAP-3 状态双通道角标/描边样式资产化（V4） | 美术（Phase 4 衣橱格子卡片包） | Phase 4 | 低 |
| GAP-4 衣橱 13 槽位 → ≤8 页签分组方案确认（C3） | ~~已闭环~~（ux-spec.md §2 定稿 8 组，2026-11-21；资产清单已对齐，C3 达标） | — | — |

**Phase 5 验收门槛：Basic 5 项 + Standard 14 项全通过**（GAP-1~4 逐项核验）；Comprehensive 档 5 项列入远期候选池，不进入 v1 验收。

## 4. 引用与维护

- UX 规格文档与 HUD/各系统 GDD 引用本矩阵时**不得低于 Standard 档**，新增可访问性特性须先在本矩阵登记档位再展开设计。
- 本矩阵与美术圣经 §9 联动维护：§9 修订（版本号变更）须同步评估本矩阵档位与缺口清单。
- 分级口径与「Basic / Standard / Comprehensive」命名供全项目统一复用（含后续 UX 规格、验收清单）。
