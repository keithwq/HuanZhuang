## 0. 导出口径速查（ADR-003 落地，全清单通用）

| 项 | 口径 |
|---|---|
| 密度目录 | 角色/服装部件、UI、图标、家具 → **`assets/@2x/`**（= 1024×2048 源稿直接发布）；背景整图、氛围光分层、光效贴图 → **`assets/@1x/`**（逻辑尺寸） |

## 5. 合计包体与内存预估

### 5.1 下载体积（未 gzip；PNG 本身已压缩，gzip 增益预计 <5%）

| 包 | 件数 | 体积预估 |
|---|---|---|
| P0 骨架 | 29 | ≈ 1.0MB |
| P1 首套联调 | 34 | ≈ 5.5MB |
| P1.5 房间 | 64 | ≈ 4.4MB |
| P2 覆盖层 UI | 10 | ≈ 0.7MB |
| **首批合计** | **137 件** | **≈ 11.5MB（±15% 观察带）** |

- **首屏关键路径 = P0 + P1 正面视图 ≈ 4.5MB**（背面视图与房间包懒加载，ADR-003 §3/§5）；
- 对照 B-04 包体感：Phaser ≈350KB(gz) + 音频 ≤500KB + **首批资产 ≈11.5MB** → v1 首批总下载 ≈ **12.4MB**；
- v1 全量推演（服装 40-50 件 × 双视图，D2-02）：滚动生产追加 ≈ 15~25MB，**v1 全量资产 ≈ 27~37MB**——静态 HTTP + CDN 承接（architecture.md §托管要求），建议 Phase 5 实测后按 cal-04-review 杠杆清单复核 @2× 发布件体积 cap（观察线 ≤300KB/件）。

### 5.2 稳态内存复核（CAL-04 通过值，TexMemAccountant 口径 w×h×4）

## 6. 生产流转与审计要求

1. **打勾制**：每件按「☐ → ◐ → ☑」流转，☑ 前须通过圣经 §5.4/§10.2 尺寸与命名审计（审计红线：命名规范 §4.4/§10.2、画布内包含校验、同行点位不重叠不适用部件但锚线对齐必查）；
2. **命名冻结**：本清单文件名即投产名，生产中改名须美术总监审批并同步引擎资产表；
3. **GAP-4 已闭环**：衣橱页签图标集按 ux-spec §2.1 定稿收敛为 **8 组（#07~14）**（G1 发型 / G2 头饰 / G3 上装 / G4 下装 / G5 外套 / G6 鞋袜 / G7 配饰 / G8 光效）；**组只是页签层**——混组内逐槽换装走物品卡（缩略图 + 角标）+ `tryOn(slot, itemId)`，无需逐槽图标，确认无遗漏；保存按钮不属类目图标集、走贴纸感文字按钮样式（如后续需要专属 icon 按批次补件）；可访问性矩阵 C3「≤8 组」达标，本项不再挂账；
4. **AI 生成提示词**：Phase 4 逐件生产时按圣经各节规格现产现写（渐变规范 §2.3、紫灰阴影、学院意象 §10.3），不入本清单正文以免规格双源。
