## 0. 总体视觉方向（已定：方向 B「梦幻幻想系」，D1-07）

用户已拍板（D1-07）：**梦幻童话 × 幻想系**。全文按方向 B 展开。

**方向定义：**
高明度渐变、光效点缀、童话礼服氛围。世界观气质是「一个属于少女自己的童话空间」——星与月光、纱与花藤、梦幻礼服。目标人群为 12-16 岁女性（D1-02），视觉情绪基调为：**明亮、梦幻、温柔、有想象力，不阴暗、不成人化、不冷峻。**

**本方向固有风险的缓解策略（承接 v0.1 对比表预警：渐变与光效在 Canvas 下的性能与文件体积）：**

| 风险 | 缓解策略 |
|---|---|
| 渐变开销 | **渐变一律预烘焙进 PNG 贴图**（源稿阶段渐变→栅格化导出），运行时零 shader 渐变计算；禁止运行时 Canvas 逐帧渐变填充 |
| 光效开销 | 光效 = 预制软边径向 PNG 贴图 + `Phaser.Sprite` 叠加（ADD 混合），同屏光效贴图 ≤ 8 张；**禁用全屏后处理滤镜**（手机 WebGL 后处理是性能刺客） |
| 文件体积 | 光效/渐变类贴图单独走压缩预算：单张 ≤ 80KB，全项目光效贴图总量 ≤ 3MB；渐变大面积色块用 8px 高条带拉伸而非全尺寸贴图 |
| 粒子压力 | 套装完成粒子 ≤ 12 粒（v0.1 为 8 粒，随幻想系放宽至 12 粒，上限封死）；粒子为预烘焙小贴图（16/32px），禁止逐粒子发光 |

**纪律继承（v0.1 有效）：** 上述缓解手段全部属于「贴图美术」范畴——幻想感来自**画出来的光**，不是**算出来的光**。这与 Phaser/Canvas 能力边界精确匹配。

## 1. 视觉支柱

三条支柱是所有资产生产与验收的最终仲裁标准。任何资产「好看但不符合支柱」即不通过。

### 支柱 1 · 聚焦不喧宾：「角色是画面的唯一主角」（承 v0.1，随 D1-07 微调措辞）
竖屏手机画幅极小，视觉焦点必须唯一。场景、UI、特效一律做减法：幻想系虽允许光效点缀，但**光效是礼服的配角**——场景亮度、对比度、动效密度永远低于角色与服装。验收标准：截图后眯眼看，第一眼必须是角色与服装，而非背景、UI 或光效。

### 支柱 2 · 每一层都值得换：「部件即奖品」（承 v0.1，D1-01 呼应）
核心玩法为自由搭配、弱评分（D1-01），审美驱动是「我搭配的这身更好看」。美术预算按**服装部件**倾斜：单个上装/下装/发型的细节密度高于场景全部元素之和。每个部件独立成立（单穿好看），组合成立（混搭不穿帮），成套升华（套装有呼应彩蛋，如同色系刺绣、主题纹样——幻想系下主题纹样升级为星座、花卉、魔法符文等成套叙事元素）。

### 支柱 3 · 手作温度 + 画出来的光：「像被人画出来的，不是被渲染出来的」（承 v0.1，随 D1-07 修订）
2D 渲染不追写实，拥抱扁平手绘：线条粗细有呼吸、色块带轻微噪点纸纹。幻想系的光效与渐变**全部遵守 §0 缓解策略**——预烘焙进贴图、以手绘笔触绘制，运行时只做贴图叠加。精致来自设计而非技术堆料。

| 色名 | HEX | 用途 |

| 星紫主色 Aster | `#8268C6` | 主操作按钮、选中态、品牌色（按钮白字对比 ≈ 3.9:1，满足大字号/图形 3:1 标准，按钮文字均为 Body-L 及以上） |

### 2.2 语义色（承 v0.1 不变，对比度纪律不变）

| 语义 | HEX | 说明 |
|---|---|---|
| 成功 | `#7FB88A` | 柔和绿，操作完成 |
| 警告 | `#E8B04B` | 柔和琥珀 |
| 错误 | `#D97566` | 柔和珊瑚红，**不做高饱和红**以免压迫感 |

| 禁用 | `#C9C0B4` | 带暖灰的禁用态 |

语义色一律与文字色 `#2E2A45` 或白色搭配使用，确保 ≥ 4.5:1 对比度（见 §9）。

### 2.3 服装色彩策略（核心资产策略，随 D1-07 梦幻童话基调微调，CAL-02 解除）

服装是全项目最大的色彩消耗方，**必须提前规划，否则必然失控。**

**分层策略——服装色板独立于 UI 色板：**
- **基础色轮（固定 12 色，梦幻童话调，D1-07）**：基准色相整体偏向「粉彩高明度 + 童话糖果」区间，允许 ±15% 明度/饱和度浮动，禁止色相漂移到色轮之外：

| # | 色名 | HEX 基准 | # | 色名 | HEX 基准 |
|---|---|---|---|---|---|
| 1 | 玫瑰 Rose | `#EF8FA3` | 7 | 星夜蓝 Star | `#7B8FD9` |
| 2 | 蜜橘 Tangerine | `#F5B37E` | 8 | 铃兰紫 Lilac | `#B49FE8` |
| 3 | 奶油黄 Butter | `#F7DD8F` | 9 | 魔法紫 Mystic | `#9A7FC9` |
| 4 | 嫩芽绿 Sprout | `#A9D98F` | 10 | 樱花粉 Cherry | `#F7B8CE` |
| 5 | 湖水青 Aqua | `#9FDCE0` | 11 | 可可棕 Cocoa | `#C49B7E` |
| 6 | 天空蓝 Sky | `#8FB8E8` | 12 | 云珠白 Pearl | `#EFEAF4` |

- **浮动色位（稀有度预留，承 v0.1）**：色轮之外额外预留 4 个「特殊色位」，只允许稀有/限定套装使用：**虹彩渐变（星空/极光）、星银金（月光金属）、珠光夜光、童话限定主题色**。幻想系下虹彩与星银金是套装「仪式感」的核心视觉稀缺资产。

**三个色彩纪律（承 v0.1）：**
1. **单部件 ≤ 3 色原则**：单个服装部件主体色 ≤ 3 色（含面料色 ×2 + 点缀色 ×1）。
2. **同色系成套呼应**：套装内所有部件共享至少 1 个点缀色，套装完成有「成套感」正反馈（联动 §8）。
3. **与 UI 抢色禁令**：服装色允许覆盖 UI 主色板色域；但**角色展示区的背景**必须保持 §2.1 雾光系低饱和，保证任何服装色（尤其虹彩/星银金特殊色）都能跳出来。

**渐变规范（v0.6 随概念 §6 终比对落文）：**
- **面料两段式渐变**：服装主色块允许**同色系两段式渐变**塑造体积（概念 §6「梦幻渐变」的落地口径）——渐变两端明度差 ≤ 25%、色相偏移 ≤ 15°，仍约束在 12 色轮 ±浮动纪律内，渐变**不豁免**「≤ 3 色」计数；
- **紫灰阴影**：阴影一律以紫灰基调（基准 `#8E86A8` 附近，允许 ±10% 浮动）**替代纯黑**——「糖霜与月光」感的颜色学根基；
- **护栏**：渐变定义**全局复用 ≤ 20 组**（色板常量表管理，新增须美术总监审批；概念 §6「性能护栏」将上限定死于本圣经）；全部预烘焙进贴图（§0 缓解策略，禁止运行时渐变计算）。

## 3. 字体与排版

### 3.1 中文字体栈（承 v0.1 不变）

```
font-family:
  "PingFang SC",        /* iOS */
  "HarmonyOS Sans SC",  /* 华为 */
```

- **Web Font 策略**：Phaser 文本优先用系统字体栈；标题若需品牌感，用 Noto Serif SC 子集化做点缀标题（幻想系下衬线标题的「童话书卷感」与 D1-07 契合），正文禁用衬线。
- 数字/价格用 `tabular-nums` 等宽数字；品牌 Logo 可用 AI 生成图片字，不进字体系统。

### 3.2 手机竖屏字号层级（逻辑基准 720px 宽设计稿，承 v0.1 不变）

| 层级 | 字号(px, @720w) | 字重 | 用途 |
|---|---|---|---|
| H1 | 44 | 700 | 页面标题（「更衣室」「我的房间」） |
| H2 | 36 | 600 | 卡片组标题、弹窗标题 |
| Body-L | 32 | 400 | 按钮文字、主要正文 |
| Body | 28 | 400 | 列表项名称、服装名 |
| Caption | 24 | 400 | 辅助说明、标签 |
| Min | 22 | 400 | **绝对下限**，仅时间戳/计数 |

换算规则：`实际渲染字号 = 表中值 × (实际屏宽 / 720)`。**最小可读字号绝对下限为 12 物理独立像素**（§9），Caption 及以下层级在小屏上不允许再缩。

**排版纪律**：竖屏单行正文 ≤ 16 个汉字；段落行高 1.5；任何文字距屏幕边缘 ≥ 24px 安全边距。

## 4. 角色设计规范

换装主体是全项目资产量最大的「骨架资产」。本节骨架结构（13 槽位图层表、逻辑画布体系、命名规范）承 v0.1 有效（D1-10 放行）；比例数值随 D1-08 重算。

### 4.1 头身比（已定：3.5 头身，D1-08，CAL-03 解除）

**按 3.5 头身展开（D1-08）。** 气质：Q 萌与少女感并存的「童话人偶感」——头部占比大于 4.5 头身方案，天然匹配梦幻童话受众（12-16 岁女性，D1-02）。

关键比例（重算）：
- **脸部占头部 55%**（承 v0.1 不变——脸部是表情与「萌感」核心载体，比例保持）；
- **头高 ≈ 全身跨度（头顶线~地线 900px 逻辑）的 1/3.5 ≈ 257px**；
- **肩宽 ≈ 1.4 头高**（较 4.5 头身方案的 1.6 收窄，Q 版肩线更圆润）；
- **腿长占全身 42%**（较 4.5 头身方案的 45% 收短，重心下移、体态更稳定可爱）；
- 肢体圆润化：手腕/脚踝不做写实收细，用柔和曲线，匹配手绘风（支柱 3）。

### 4.2 体态基调（承 v0.1，微调）

- **站姿 A 姿（正面微侧 15°）**：默认展示姿态，双臂自然下垂微张（离开躯干 ~10°），保证袖口/手持物不遮挡躯干服装。
- **微 S 曲线**：腰线内收 3°、头部微倾 2°。3.5 头身下头部微倾幅度收紧至 1.5°（头部质量大，倾角过大会失稳）。
- **表情基调**：默认「浅微笑 + 睁眼」，眼睛为风格重点（大而亮、高光点统一在右上）；眨眼等作为动效层（§8），不作为独立姿态资产。

### 4.3 部件图层结构（图层槽位总表，承 v0.1，D1-10 放行）

角色由以下**槽位（Slot）**构成，每个槽位 = 一个独立资产类别。槽位数即服装系统的深度上限，后续新增槽位（如翅膀/尾巴）须走美术圣经修订流程。

**全局叠放顺序（正面视图，自下而上）：**

| 层序 | 槽位代码 | 中文名 | 说明 |
|---|---|---|---|
| L00 | `BK` | 背景装饰 | 翅膀、披风后摆、光环（幻想系下此槽位价值上升） |
| L01 | `BODY` | 身体基底 | 肤色、基础内衣（不可卸载的遮蔽层） |
| L02 | `HAIR_B` | 发型·后层 | 长发的脑后部分 |
| L03 | `LEG` | 鞋袜 | 袜 → 鞋，同槽内固定先袜后鞋 |
| L04 | `BTM` | 下装 | 裙/裤 |
| L05 | `TOP` | 上装/连衣裙 | 连衣裙占位在此，同时遮蔽 BTM 槽 |
| L06 | `OUT` | 外套 | 大衣、斗篷 |
| L07 | `HAND` | 手持 | 左手、右手各一挂点 |
| L08 | `NECK` | 颈饰 | 项链、围巾 |
| L09 | `HAIR_F` | 发型·前层 | 刘海、垂脸发丝 |
| L10 | `HEAD` | 头饰 | 帽子、发夹 |
| L11 | `FACE` | 面饰 | 眼镜、面具、腮红贴 |
| L12 | `FX` | 前景特效 | 前景光点、纱幔（克制使用） |

**规则（承 v0.1）：**
- 每槽位同时**最多 1 件**（HAND 槽左右手可各 1 件），v1 不支持多件叠穿。
- 「连衣裙」逻辑：资产注册为 TOP，渲染时引擎隐藏 BTM 槽已选资产（保留选择状态）。
- 槽位内渲染顺序固定，任何服装设计不得依赖打破全局层序。

### 4.4 命名规范（承 v0.1，增补背视图后缀，见 §4.5）

```
{项目代号}_{角色ID}_{槽位代码}_{系列名}_{部件名}_{变体}[_back]_{版本}.png
正面示例：  HZ_char01_TOP_starfall_gown_dress_a_v001.png
背面上例：  HZ_char01_TOP_starfall_gown_dress_a_back_v001.png
```

- 全小写、下划线分隔、禁用中文与空格；正面视图不带后缀（默认），背面视图加 `_back`。
- 系列名 = 套装主题 slug；变体 `a/b/c…` 表同款配色；版本 `v001` 起，废弃版本移入 `assets/_trash/`。

### 4.5 正/背双视图资产评估（D1-09：人物 180 度自由旋转）

用户拍板（D1-09）：人物可 180° 自由旋转查看正/背面。**纯 2D 管线下「旋转」实为「双视图切换 + 过渡动效」**，评估如下。

**三方案对比：**

| 方案 | 描述 | 资产量 | 优点 | 缺点 |
|---|---|---|---|---|
| a. 全量双视图 | 每部件出正面 + 背面两套图，对齐同一锚线网格 | 约 ×2（按 60% 精度折算实际工时 ×1.6~1.8，见下） | 体验完整，长裙/披风/长发/翅膀的背面即「高价值展示面」不被浪费；混搭永不穿帮 | 资产与纹理成本最高 |
| b. 背面简化策略 | 仅高价值部件（HAIR_B/裙摆/披风/翅膀）出背面，其余正面复用 | 约 ×1.3 | 成本低 | **混搭穿帮**：正面复杂、背面缺失的部件旋转后露馅，自由搭配玩法（D1-01）下穿帮概率随衣橱扩容线性上升 |
| c. 镜像翻转 | 运行时 `scaleX = -1` 镜像正面图 | ×1 | 零成本 | 背面变「镜像正面」，逻辑荒谬（背部出现正脸纹样），直接否决 |

**推荐结论：方案 a「全量双视图 + 分级精度 + 懒加载」（已确认，D2-01）**：
1. **全量覆盖**：所有槽位部件一律产出正/背两套图，杜绝混搭穿帮；
2. **分级精度压成本**：背面视图允许**省略不可见信息 + 细节降级**——无五官、无正面纹样、褶皱/刺绣简化至 60% 精度（发型后层 HAIR_B 与 BK 翅膀类是背面「主角」，保持 100% 精度）。工时估算 **×1.6~1.8** 而非 ×2；
3. **懒加载控内存**：默认常驻正面视图纹理；旋转手势触发时 300ms 过渡动效内预载背面纹理、卸载正面纹理。**稳态纹理内存 ≈ 单视图水平（≤ 45MB）；切换瞬时峰值 ≈ 70~75MB**（§5.5 预算，CAL-04 已核对通过，v0.7 归档）。

**背视图图层顺序（与正面表镜像逻辑独立定义，自下而上）：**

| 层序 | 槽位 | 说明 |
|---|---|---|
| B-L00 | `HAIR_F` | 刘海处于最远端，几乎不可见 |
| B-L01 | `BODY` | 身体背面（无五官） |
| B-L02 | `LEG` | 鞋袜背面 |
| B-L03 | `BTM` | 下装背面 |
| B-L04 | `TOP` | 上装背面 |
| B-L05 | `OUT` | 外套/斗篷背面（幻想系斗篷的背面是 showcase 位） |
| B-L06 | `HAND` | 手持 |
| B-L07 | `NECK` | 颈饰背面 |
| B-L08 | `HAIR_B` | 发型后层——背视图的视觉主角，100% 精度 |
| B-L09 | `HEAD` | 头饰后沿 |
| B-L10 | `BK` | 翅膀/光环——背视图时处于最近端，100% 精度 |
| B-L11 | `FX` | 前景特效 |
| — | `FACE` | **背视图不渲染** |

**过渡动效（联动 §8）：** 正→背旋转 = 角色 3 帧转身剪影过渡（300ms，角色水平压缩至 8% 再展开），期间完成纹理换装。减敏模式下（§9.4）直接 100ms 淡切。

### 5.3 部件切割原则（承 v0.1 不变）

1. **一切以 BODY 基底为准**：BODY 先行定稿并冻结，服装部件在其上「贴身绘制 + 溢出 4~6px 缝合边」。
2. **切缝即遮蔽缝**：切割线落在身体自然遮蔽处（腰线、肩缝、大腿根）。
3. **单部件单文件**：每槽位每部件 = 1 张透明底 PNG；**双视图下 = 正面 1 张 + 背面 1 张，两文件（§4.5）**。
4. **HAIR 前后层是发型的两半**：同一发型固定产出 `HAIR_B` + `HAIR_F` 同前缀两图；双视图下另增两张背面图。
5. **背视图紧裁剪（v0.7 导出口径，ADR-003）**：背面 60% 精度件允许**紧裁剪导出**（裁掉透明像素面积以压缩体积）；紧裁剪偏移量写入资产 manifest 的 **frame 数据**，引擎侧按 frame 偏移复原画布内定位（对齐 paperdoll-render §5.2「背视图紧裁剪件偏移在 frame 数据复原」口径）。正面视图与 100% 精度背面件（HAIR_B/BK 类）**不适用**紧裁剪，维持整画布导出。

### 5.4 部件尺寸规范（逻辑画布内安全区，随 3.5 头身头部放大微调）

| 槽位 | 最大占画布比例 | 约束 |
|---|---|---|
| BODY | 高 ≤ 900（头顶线~地线） | 定稿冻结（正/背各一张） |
| HAIR_B/F | 各 ≤ 240 宽（头部外扩 ≤ 45px，头大随放） | 不得遮过眼线下 20px |
| TOP / BTM | 宽 ≤ 340（中轴 ±170） | 裙摆下缘 ≥ 膝线上 40px（超长裙单独审批） |
| OUT | 宽 ≤ 380 | 外套必须比内层 TOP 宽 ≥ 8px |
| LEG | 高 ≤ 150（踝线起向上，腿部缩短随调） | 鞋底必须贴地线 |
| HAND | ≤ 120×120 | 以挂点为中心，不得遮挡躯干中线 |
| NECK/HEAD/FACE | ≤ 200×200（头部放大随调） | 头饰上缘不得超头顶线上 40px |
| BK / FX | ≤ 512 宽 | FX 透明度 ≤ 30% |

### 5.5 导出格式与预算（CAL-04 已闭环：程基岩核对通过，三档预算成立数值零修正，v0.7 归档）

- 格式：PNG-32（透明通道必须）；色彩空间 sRGB。
- 单文件 ≤ 150KB（普通部件）/ ≤ 80KB（光效渐变类，§0 缓解策略）。
- **纹理内存预算重估（双视图懒加载模式下）：**
  - 稳态（任意时刻常驻一套视图）：**≤ 45MB**（v0.1 为 40MB，3.5 头身头部贴图占比略增）；
  - 旋转切换瞬时峰值（正/背两套短时共存 ≈ 300ms）：**≤ 75MB**；
  - 房间装饰场景叠加装饰后：**≤ 60MB**（§10 草案，Phase 2 细化）。
- 缩放链（承 v0.1）：源稿 2 倍（1024×2048）→ 导出 512×1024 逻辑版 → Phaser 按 DPR 缩放；**DPR=3 设备由渲染上限 `min(DPR, 2)` 策略承接（CAL-04 核对通过，程基岩）**。
- **背景/场景类 @1× 导出档（v0.7，ADR-003）**：房间背景、场景类贴图（非服装部件、非 UI 精细节）按 **@1×（逻辑尺寸）导出**即可，不要求 2× 源稿缩放链——DPR=3 模糊风险由上述 `min(DPR,2)` 渲染上限兜底；此为纹理预算成立的前提之一，背景类超出 @1× 需求的导出须美术总监单独审批。

## 8. 动效与反馈原则（承 v0.1，随 D1-09/D1-07 增补）

**触屏语境总原则：动效是「确认反馈」而非「表演」。单次反馈动效 ≤ 300ms，全程可打断，可全局关闭（§9）。常驻白名单维持 3 项（D1-11 放行）。**

### 8.1 核心动效表（v0.2 增补旋转项）

| 事件 | 动效设计 | 时长 |
|---|---|---|
| **换装确认** | 旧部件 100ms 淡出 → 新部件从挂点/腰线 150ms 淡入 + 2% 上浮落定 | ≤ 300ms |
| **正/背旋转（D1-09）** | 3 帧转身剪影过渡（水平压缩至 8% 再展开），期间完成双视图纹理换装 | ≤ 300ms |
| **套装完成** | 全身柔和 1 次光晕呼吸（描边发亮 0→30%→0）+ 同点缀色星尘粒子 **≤ 12 粒**（幻想系随调，上限封死）+ 轻微「叮」感（音频归阮和鸣） | ≤ 800ms，一次性 |
| **误触/不可用** | 按钮 3° 摇头 200ms；禁用红闪（柔性错误） | 200ms |

### 8.2 常驻微动效（克制白名单，D1-11 放行，仅 3 项）

1. 角色呼吸：躯干整体 ±1% 缩放，3s 周期；
2. 眼睛眨眼：8s 周期随机 ±2s，闭眼 120ms；
3. 发梢/裙摆微风摆动：HAIR_F 底部发丝与 BTM 裙摆下缘 ±2px 水平摆动，4s 周期。

白名单之外的循环动效默认拒绝，需美术总监单独审批。**幻想系的星灯/光点呼吸 temptation 一律拦截**——场景光是画的，不是跳的（§0 纪律）。

## 9. 可访问性基线（承 v0.1 不降级；§9.6 随 D1-02 新增）

### 9.1 对比度

| 项 | 标准 |
|---|---|
| 正文文字 vs 背景 | ≥ 4.5:1（WCAG AA） |
| 大字号(H1/H2)与图形 | ≥ 3:1 |

### 9.2 色弱友好（承 v0.1）
