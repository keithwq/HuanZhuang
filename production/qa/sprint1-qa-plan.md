## 2. M1 出口验证方案（三红线 + 帧采样 + 页签走查 + 懒加载）

### 2.0 取证基础设施（前置要求，向程基岩经主理人提）

1. **测试探针（dev-only）**：`window.__hz` 桥暴露 performance mark——`tap_in`（pointerup 时刻）与 `render_commit`（合成器落帧时刻）、旋转 `flip_start/flip_commit`、texmem 报表查询。**生产构建必须零暴露**（`import.meta.env.DEV` 门控，代码评审项）。
2. Playwright 设备三档（承 testing-scaffold §2.2）：iPhone 14 Pro 仿真（DPR=3，验 R-14 cap=2：断言 canvas 后备存储宽 = CSS × 2）、中端 Android（DPR=2.6 长屏自适应）、低端 Android（4x CPU 限速，30fps 容忍线采样）。
3. 采样统计口径：每红线 **≥30 次样本**，报告 p50/p95/max 三值；PASS 判据 = **max ≤ 300ms**（红线是逐次承诺，非均值承诺——单次超标即 FAIL，不取平均掩盖）。CI 机器慢于真机时允许复测确认，不许改口径。

### 2.1 红线一：点选→变装 ≤300ms（R-01 · wardrobe §8.1 / paperdoll §8.2）

- **口径定义**：从 `pointerup`（点选卡片抬起）到角色画面首次可见变化帧的时间戳差。"可见变化"= 换装确认动效第一帧（旧件开始淡出），非最终落定帧。
- **取证方式**：
  - Playwright（iPhone 仿真）：30 次点选采样（跨 8 组各取若干），断言 max ≤300ms，原始数据落 `tests/evidence/latency-tryon.md`；
  - 补充真机 1 台（中端 Android）：Chrome 远程调试 + 同探针，10 次样本佐证（真机记录 env + 数据入同一证据文件）；
  - 背面视图下点选：同口径采样（wardrobe §2.2 缩略图不随旋转变、300ms 内角色台同步换装）。
- **伴随断言**：点选卡片 = 当前穿着 → 仅轻反馈（微缩放 100ms）、无状态变化（wardrobe §2.2）。

### 2.2 红线二：旋转过渡 ≤300ms（R-02 · paperdoll §8.2/§2.2）

- **口径定义**：`flip_start`（拖拽释放/按钮点按）到 `flip_commit`（新视图首帧展开）。
- **取证方式**：
  - 路径 B 按钮 + 路径 A 手势（Playwright touch 事件模拟横向拖拽，起点落全宽×96px 拖拽区，paperdoll §2.2 路径 A）各 30 次；
  - **过渡中再翻转被忽略**（paperdoll §5.3 无旋转队列）：脚本在过渡中连续 3 次触发，断言零队列出错、最终视图正确；
  - **减敏通道**（R-15）：`reducedMotion: 'reduce'` 仿真下断言 100ms 交叉淡切、无压缩转身、不预载剪影 3 帧（paperdoll §5.7）；
  - 纹理迟到兜底（paperdoll §5.3）：人为节流网络使目标视图纹理 >300ms 才到 → 断言旧视图淡切补完、**零空槽/白体**。
- **伴随断言**：拖拽区与抽屉无重叠、跨界滑动不触发翻转（paperdoll §5.6）。

### 2.3 红线三：动效可打断（R-01/R-08 · paperdoll §8.2/§8.6）

- **口径定义**：换装/旋转动效进行中，下一操作到达即中止当前动效、立即进新状态；无卡死态、无队列、不吞点击。
- **取证方式**（Playwright 脚本 + 单测双轨）：
  - 脚本以 10 次/秒连点异组卡片持续 3 秒（wardrobe §5.6 极端连点口径）→ 断言：最终装扮 = 最后一次点选；stats.tryOnTotal 增量 = 实际点选有效次数；无中间态残留（探针读当前 tween 计数归零后稳定）；
  - 旋转过渡中点选换装（跨红线交叉打断）→ 断言新换装即时生效、旋转状态一致；
  - 单测层：tweenSvc guard 契约（白名单外循环动效运行时拒绝，R-08）+ 打断路径状态机用例（E2-S04 测试先行清单）；
  - 证据落 `tests/evidence/latency-tryon.md`（打断专项小节）。
- **伴随断言**：60fps 下白名单常驻 3 项在跑（呼吸/眨眼/裙摆），无白名单外循环动效（控制台零 guard 违规输出，R-08）。

### 2.4 60fps 帧采样口径（R-04 · paperdoll §8.7 / wardrobe §8.2）

- **采样方法**：dev 探针记录 rAF 帧间隔（或 Phaser debug FPS 计数），采样场景 = 连续滑动抽屉 + 页签切换 + 点选换装混操作 60 秒；
- **判据**：60fps 目标下无可感知卡顿——采样期 p95 帧间隔 ≤ 16.7ms×1.5（约 ≥40fps 无长帧即"无可感知卡顿"的操作化口径，p95 连续掉帧段 < 3 帧记 PASS 附数据；**数值口径由本计划定义并报主理人备案**，GDD 原文只承诺"无可感知卡顿"）；
- **低端档**（4x CPU 限速仿真 + 真机低档 1 台）：容忍 30fps，断言**动效时长不变、帧数减半**（paperdoll §4：以探针时长采样验证，动效总时长不因帧率改变）；
- **伴随断言**：抽屉连续滑动 + 点选混操作全程无掉帧段（wardrobe §8.2）；
- 证据落 `tests/evidence/framerate.md`（含低端档时长不变专项）。

## 4. testing-scaffold.md 独立评审（验证方视角，非实现方）

**总判定：CONCERNS——结构合格可开工，但 4 项盲区须在首批用例落地时补齐，另有 2 项口径待主理人备案。**（OK 项不列：三层结构/测试先行/红线静态扫描表/证据命名约定均与 checklist、cal-04 §7 对齐，无异议。）

### 4.1 CONCERNS 清单

| # | 盲区 | 风险 | 补充要求（并入首批用例） |
|---|---|---|---|
| C-1 | **动效时长在 headless 下的可测性**：`fakeTimers` 控制的是 vitest 时钟，Phaser tween 走引擎自有步进（rAF/ticker），jsdom 里两者不自动咬合——headless 下"300ms 时序断言"很可能测不到真实行为 | 红线时长在单测层假绿 | 单测层只断言**配置值**（tween duration 常量表 = GDD §4 数值）；**真实时长一律归 Playwright + dev 探针**（§2.0 前置项）。若程基岩用 ticker 注入法在 headless 驱动时序，须先向本席演示一次采样再采信 |
| C-2 | **jsdom localStorage 模拟真实性**：jsdom 是纯内存实现——无配额、无私有模式抛异常行为、无 Safari 私有态怪癖；U-01/U-02 在 jsdom 里"绿"不代表真浏览器绿 | 存档红线假绿 | StorageDriver 保持**可注入**（hostile fake driver 单测：抛异常/配额拒绝逐个注入）；真浏览器权威归 Playwright 隐私仿真（T-05）；真机 Safari 私有模式 1 台佐证列入 Sprint 1 末走查 |
| C-3 | **契约快照漏运行时行为**：签名快照防"改接口"，防不了"接口没改但行为漂移"（tryOn 变异步、onTryOn 漏发/重发、事件乱序） | 防漂移网眼太大 | 增补**行为契约用例**：每次成功 tryOn/unequip → onTryOn 恰发 1 次、payload schema 断言、事件次序（tap→tryon:done→stats）固定；并把 GDD §6 接口表本体作为测试数据文件——GDD 修订必须显式过快照 diff |
| C-4 | **e2e 红线断言的 flaky 面**：单次硬断言 max ≤300ms 在 CI 抖动机器上会偶发红，污染信号 | 质量门噪声 | 保留 max 判据不放宽（红线是逐次承诺），但规范：CI 红必须同机复测 2 次定案、失败样本原始数据留档；禁止用改阈值"修 flaky" |
| C-5 | **`page.on('console')` 告警断言依赖构建配置**：dev 构建的 verbose 日志会误报 texmem 告警 | 假红/假绿 | 断言仅在 `mode: production` 构建下执行，Playwright config 注明 |
| C-6 | **覆盖面缺口**：本计划 §2.5 T-01~T-14 中，脚手架 §3 已覆盖分组/筛选/连点/成对/解耦，但**缺**：① 拖拽手势路径 A 的 touch 仿真用例（脚手架 e2e 未列 rotation 拖拽）；② R-14 cap=2 的 canvas 后备存储断言；③ 视口外缩略图零请求的网络监听断言；④ 摇头 200ms 反馈时长用例 | GAP-4 与 R 红线取证面不全 | 按 §2 各节取证方式补入 e2e/ 首批清单 |

## 6. 执行节奏与报告格式

1. **触发**：程基岩 E1 全绿回传（经主理人转）→ 本席执行第一轮验证：复跑单测/契约套件（独立环境，不采信其自测输出）→ §3 烟雾 → Story 逐项按 §1 表取证；
2. **每轮 QA 报告**（呈主理人转用户）：逐 Story 判定 PASS/CONCERNS/FAIL + 证据路径 + 缺口清单（含 Bug 报告：环境/前置/步骤/预期/实际 + 严重度 Blocker/Critical/Major/Minor）；
3. **flaky 纪律**：任何断言两次结果不一致 → 立即隔离（skip 标记 + 归因），CI 信号不许被污染；
4. **M1 质量门判定**：三红线 + 帧采样 + 页签走查 + 懒加载四板块全 PASS 且 fh 补测闭环（或经主理人确认挂账）→ 建议 PASS；任一红线 FAIL → 建议 FAIL 并列阻塞项。
